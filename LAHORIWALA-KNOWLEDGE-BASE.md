## 3. POSITIONING — the single most important thing to get right

LAHORIWALA is **affordable neighbourhood Lahori food presented cinematically.**

The agreed formula: **"Street food royalty" — luxury craft, everyday price.**

| Do | Don't |
|---|---|
| Show real prices proudly | Hide prices behind "POA" |
| Premium *craft* | Premium *price* |
| Warm, proud, generous | Exclusive, allocation-only, fine-dining |
| Cinematic photography and motion | Mayfair pretension |

The old site presented a fictional Mayfair fine-dining restaurant. That was
removed entirely. A customer arriving expecting Mayfair and finding a £5.99
curry would feel misled — the mismatch is the failure mode to avoid.

### Audience, in priority order
1. **London Pakistani / desi community** — they already know what nihari and
   karahi are. Write with pride and nostalgia, *never* tourist-style glossary
   copy.
2. **Families and large groups** — warmth, generosity, occasion.
3. **Premium / fine-dining diners** — restraint, provenance, quiet confidence.

Avoid both extremes: no dumbed-down explanation, no cold luxury-brand voice.

## 4. BRAND & DESIGN SYSTEM

### Palette — every value measured against WCAG 2.1, not eyeballed

**Dark theme (the default, and the brand's identity):**
| Token | Hex | Contrast on base |
|---|---|---|
| `brand-base` | `#0D0D0F` | — |
| `brand-raise` | `#141316` | — |
| `brand-surface` | `#F5EFEB` | 17.04:1 AAA |
| `brand-muted` | `#9E988F` | 6.79:1 AA |
| `brand-accent` (gold) | `#E5A93C` | 9.31:1 AAA |
| `brand-green` | `#155E3B` | fills only |
| `brand-green-light` | `#58A878` | 6.74:1 AA |
| `brand-hot` | `#F0925A` | 8.29:1 |

**Light theme — NOT an inversion:**
| Token | Hex | Contrast on base |
|---|---|---|
| `brand-base` | `#F7F3EE` (warm paper, not white) | — |
| `brand-raise` | `#EFE9E1` | — |
| `brand-surface` | `#17130F` | 16.73:1 AAA |
| `brand-muted` | `#5A534A` | 6.86:1 AA |
| `brand-accent` | `#7A4E06` (deep ochre) | 6.51:1 AA |
| `brand-green` | `#14532D` | fills only |
| `brand-green-light` | `#14653A` | 6.44:1 AA |
| `brand-hot` | `#9A3412` | 6.61:1 |

> **Why light mode needs its own gold:** `#E5A93C` on cream measures **1.86:1**
> — unreadable. A naive inversion breaks the accent. This is the single most
> important colour lesson from the project.

**Theme-invariant tokens** (never change between themes):
| Token | Hex | Use |
|---|---|---|
| `scrim` | `#08080A` | gradients over photographs |
| `on-image` | `#F5EFEB` | text sitting on photographs |
| `accent-on-image` | `#E5A93C` | gold sitting on photographs |

> **Why:** photography needs a **dark** scrim in *both* themes. A cream scrim
> over a photo washes it out and strands overlaid text with no contrast. So
> full-bleed image sections stay deliberate **dark islands** in light mode. And
> the light accent on a dark scrim measures **2.78:1** — hence a pinned gold.

### Typography
- **Headings:** Bodoni Moda, italic, light weight — via `next/font/google`
- **Body:** Manrope
- **Metadata / data / numbers:** monospace (`font-mono`), uppercase, wide tracking
- Display headings: tight tracking (`-0.02em` to `-0.03em`), low line-height
  (`0.86`–`0.95`), `clamp()` sizing up to ~13vw

### Motion vocabulary
- `EASE_LAHORI` = `cubic-bezier(0.16, 1, 0.3, 1)` — the house curve, used by
  every reveal. Tailwind utility: `ease-lahori`
- `EASE_SEAL` = `cubic-bezier(0.76, 0, 0.24, 1)` — overlays, curtains, clip-paths.
  Utility: `ease-seal`
- Shared variants live in `src/lib/motion.ts`: `fadeUp`, `maskUp`, `wordUp`,
  `stagger()`, `inView`

### Visual language — what "modern" means for this brand
| Use | Avoid |
|---|---|
| Hairline rules as structure | `rounded-2xl` bordered cards |
| Monospace metadata | Small gold uppercase labels repeated every section |
| Asymmetric / offset grids | Everything centred in a max-width container |
| Full-bleed imagery, type overlapping | Small boxed photos in grids |
| Huge display type, generous whitespace | Uniform medium-sized headings |
| Numbered editorial indexes | Card carousels |

> **The single biggest "cheap-looking" mistake made on this project:** five
> consecutive sections all sharing one skeleton — *small gold uppercase label →
> italic heading → grey paragraph → grid of rounded cards.* The repetition of
> shape is what reads as "template", not the colours.

## 5. ARCHITECTURE — patterns worth carrying forward

The website is Next.js 16 / React 19 / Tailwind v4 / Framer Motion / GSAP /
Lenis / lucide-react. **A different tool may not use these** — but the
*patterns* below are what matter.

### The dashboard seam (owner's explicit requirement)
An admin dashboard is planned so the owner can edit the menu himself. He wants
it discussed **after** the frontend is complete, but designed for from the start.

- Content lives in a **typed data layer**, never inline in components
- `src/data/menu.ts` — the 98 dishes
- `src/lib/menu.ts` — thin accessor functions; **this is the swap point.** When
  the dashboard lands, only this file changes and no rendering code is touched
- `src/lib/site.ts` — every business fact, single source of truth
- `src/data/images.ts` — every photograph, single source of truth

> The old build hardcoded dish arrays inside three separate components and had
> **two different addresses and two different phone numbers live at once**,
> because each component carried its own copy.

### Dish model — deliberately small
```ts
{ id, name, price: number | null, priceNote?, description?,
  composition?, image?, tags?: ("veg"|"spicy"|"sharing"|"breakfast"|"signature")[] }
```
The owner asked for **core fields only** — photo, name, price, short
description. He explicitly rejected per-dish spice level, allergens, heritage
and cooking method. Resist adding fields he didn't ask for.
`price: null` renders as "Ask in store" — never "£null" or a guess.

### Honest-by-default UI (important principle)
Where a fact is unknown, the UI **asks instead of asserting**:
- Opening hours unconfirmed → "Call ahead for today's serving times", and the
  "open now" badge is suppressed entirely
- Social/delivery URLs unconfirmed → rendered as **inert badges, not dead links**
- The reservation form **never says "confirmed"** — `submitReservation()` sends
  nothing anywhere yet, so it says the table is *not held* and asks the customer
  to ring. **Do not reword this until a real backend exists** — otherwise people
  arrive at a restaurant that never heard of them.

### Image resilience
`SmartImage` wraps the image component with an `onError` fallback that renders a
designed charcoal gradient carrying the dish name. **Three of twelve Unsplash
IDs had rotted to 404**, including the hero's largest image, which was rendering
as an empty box. Never trust a remote image URL to survive.

### Theme switching without flash
A **blocking inline script in `<head>`** reads storage and sets `data-theme`
before first paint. A bundled module arrives *after* paint — that is the usual
cause of theme flicker. `<html>` needs `suppressHydrationWarning`.

### Scoped token re-mapping (elegant trick worth reusing)
Pages opening with a dark photo hero set `data-over-dark` on the header, and CSS
re-points the tokens **for that subtree only**:
```css
[data-over-dark="true"] {
  --color-brand-surface: var(--color-on-image);
  --color-brand-accent:  var(--color-accent-on-image);
}
```
Every child becomes cream/gold automatically — no prop threading through
wordmark, links, buttons and toggles.

## 6. CONTENT RULES — what must never be invented

**Never fabricate a history for a real business.** The original site asserted
dated milestones ("1947 The Walled City", "1962 Akbari Mandi") as LAHORIWALA's
own story. That is a fabricated biography on a live commercial site. It was
removed.

The heritage page instead describes the **heritage of the food** — Lahori
street-food origins, the overnight nihari pot, live charcoal, nashta culture —
which is checkable, and links each chapter to real dishes on the menu.

**When the owner supplies his real family story, it becomes chapter 01.**

Similarly: no invented catering per-head prices, no invented opening hours, no
invented contact details.

## 8. PERFORMANCE — expensive mistakes, already paid for

These were all introduced and then removed on this project. **Do not
reintroduce them.**

| Pattern | Why it's slow |
|---|---|
| **`mix-blend-mode` on a fixed, full-viewport element** | Forces the compositor to read the backdrop — the entire scrolling page — and re-blend every frame. **This was the main cause of jank.** Static grain is cheap; the *blend mode* is not. |
| **`will-change` on a very large element** | A 5-viewport-wide horizontal track (~9600px) was pinned into GPU memory as one enormous texture. GSAP's `force3D` already promotes only while tweening. |
| **`backdrop-filter` / blur over scrolling content** | Reliable way to lose frames on mid-range Android. |
| **One `whileInView` per list item** | 98 dishes meant 98 IntersectionObservers registered at mount. Inherit a variant from one parent instead: 15 observers, and the parent handles stagger. |
| **Multiple competing rAF loops** | Consolidated to a single GSAP ticker that Lenis already drives. |
| **Animating `filter`, `box-shadow`, `width`, `left`** | Forces paint or layout every frame. **Animate only `transform` and `opacity`** (plus `clip-path`, which is composited). |

### Other performance rules
- Gate continuous loops and ScrollTriggers behind viewport proximity — nothing
  animates off-screen
- Canvas effects: cap DPR at 2, pool particles, pause on `visibilitychange` and
  via IntersectionObserver, disable below 768px
- **No pinned horizontal scroll on mobile** — it fights the browser's own
  gesture handling and address-bar resize. Give phones stacked full-bleed panels
- Reduce parallax depth on phones; the same travel over a short viewport reads
  as a jolt
- Respect `prefers-reduced-motion` everywhere

## 9. ACCESSIBILITY TRAPS HIT ON THIS PROJECT

- **Per-word motion typography destroys text.** `text.split(" ").map(...)` with
  CSS margins for spacing produces markup whose text content reads
  `Lahore,cookedinNorbury.` to screen readers, crawlers, translation tools and
  copy-paste. **Keep a real space text node between the mask wrappers.**
- **Low-opacity text fails on light backgrounds.** Placeholders at `/30`
  measured 1.95:1; `/45` still failed at 2.94:1. `/60` passes both themes.
- **Raw Tailwind palette colours don't survive theming.** `orange-300` was fine
  on dark, ~2:1 on cream. Use semantic tokens.
- **Never hardcode `color-scheme`** — a pinned `[color-scheme:dark]` left the
  native date picker dark on a light page.
- Keyboard focus must stay visible in both themes.
- A preloader must **never gate the page.** The old one rendered
  `{isLoaded && <everything/>}`, so the homepage shipped **20KB of HTML** while
  `/menu` shipped 222KB — search engines saw an empty page. Make it a
  self-contained overlay: content renders underneath, plays once per session,
  dismissable by tap/scroll/key, skipped under reduced motion.

## 10. NEXT.JS 16 BREAKING CHANGES (if the next tool is also Next.js)

The project's `AGENTS.md` instructs: **read `node_modules/next/dist/docs/`
before writing code.** Real issues found:

1. **`images.qualities` now defaults to `[75]`.** Any other `quality` prop is
   silently coerced. Declare the values you use in `next.config.ts`.
2. **`priority` on `<Image>` is deprecated** → use `preload`.
3. **Next no longer overrides `scroll-behavior`** during navigation. Add
   `data-scroll-behavior="smooth"` to `<html>` or route changes fight Lenis.
4. `middleware` → renamed `proxy`. Async request APIs are now async-only.
5. Tailwind v4: `bg-gradient-to-*` → `bg-linear-to-*`.
